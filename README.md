# 星口 StarPort

从本机 Clash 配置里挑少量节点，每个节点开一个只听 `127.0.0.1` 的 socks 端口，用一个页面增删、启动、停止。人和本机上的 AI 都调用这个页面，不把订阅地址和节点密码放进仓库。

星口只管理自己拉起的那一份 mihomo。Clash Verge 正在用的系统代理和 TUN 不动。

## 跑起来

```bash
go build -o starport ./cmd/starport
cp config.example.yaml config.yaml
./starport
```

浏览器打开 [http://127.0.0.1:18765](http://127.0.0.1:18765)。`config.yaml` 和 `data/` 只留在本机，已经写进 `.gitignore`。

留空 `profile` 时，读取 Clash Verge 当前选中的那份配置文件，只用文件路径和节点显示名。订阅链接不会出现在页面和接口里。

启动时写出的 `data/runtime.yaml` 只含选中的节点，权限 `0600`。没选中的节点不会写进去，所以也不会占着内存。

## 给 AI 的接口

管理页只听本机，没有另设口令。

- `GET /api/status`：后台程序、已保存的出口、实际打开的端口
- `GET /api/catalog`：节点显示名。订阅提示（更新订阅、激活订阅、禁止使用）会藏起来
- `POST /api/exits`，正文 `{"name":"节点全名","port":18008}`。`port` 为 0 时从 `18001` 起找空位
- `DELETE /api/exits/{port}`
- `POST /api/start`：按当前列表生成配置并启动。已经在跑就先停再起
- `POST /api/stop`
- `GET /api/agents`：正在使用的地址，形如 `socks5h://127.0.0.1:18008`

`socks5h` 表示域名由代理解析，避免被 Clash 的假 IP 带偏。添加和删除先记在列表里，要点一次启动才换成新端口。

## 内存

测的是 Mihomo Meta v1.19.33，darwin arm64，进程起来约 1.5 秒、还没有转发流量。RSS 是 `ps` 的驻留内存，物理占用是 `vmmap` 的 Physical footprint。

只增加本地端口、后面都是 DIRECT，不加载真实节点：

| 端口数 | RSS | 物理占用 |
| --- | --- | --- |
| 0 | 31280 KB | 13.4 MB |
| 1 | 31728 KB | 13.3 MB |
| 10 | 32144 KB | 13.5 MB |
| 50 | 33904 KB | 14.8 MB |
| 91 | 34720 KB | 15.5 MB |

从 1 个端口到 91 个，多出来的 90 个端口合计 RSS 2992 KB，平均每个端口大约 33 KB。物理占用从 13.3 MB 到 15.5 MB，平均每个大约 25 KB。

用真实订阅里的节点，每个节点再配一个端口，DNS 关掉，地理库只做了链接、这一步还没被碰过：

| 出口数 | RSS | 物理占用 |
| --- | --- | --- |
| 1 | 32400 KB | 13.5 MB |
| 3 | 32624 KB | 13.6 MB |
| 91 | 36048 KB | 16.5 MB |

从一个真实出口到 91 个，多出来的 90 个合计 RSS 3648 KB，平均每个大约 41 KB。物理占用从 13.5 MB 到 16.5 MB，平均每个大约 34 KB。3 个出口比 91 个少大约 3.3 MB RSS。

底座大约是 32 MB RSS、13.5 MB 物理占用。每多一个出口，闲着的时候大约再加 40 KB RSS、30 KB 出头的物理占用。地理库是一次性的：一份已经跑起来、规则和地理库都被用过的 91 口进程，测到 RSS 29728 KB，物理占用 25.0 MB。这 25 MB 里大头是地理库被碰过后留在物理内存里，不是第 91 个端口。刚拉起的 3 个真实出口是 RSS 33488 KB，物理占用 14.0 MB。两边物理占用差得更多，是因为那份 91 口进程已经把地理库碰进了物理内存，不是因为每个出口值几 MB。

没有测「正在传数据时每个连接再占多少」。那一块跟当时的流量有关，不跟出口个数成固定比例。

## 不进仓库的东西

- `config.yaml`：本机 mihomo 路径、配置文件路径
- `data/`：选中的端口、生成的运行配置、日志、pid
- Clash 订阅地址、节点 UUID、密码、服务器地址

页面和 `/api/catalog` 只返回节点显示名。
